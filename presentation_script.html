Likely Judge Questions — Prepared Answers

Q: "What if someone tampers AND re-registers the document?" A: "They can't. The genesis hash is locked at creation. Any re-registration creates a new chain with a different ID. The original chain's tamper flag remains permanent." (Sanika answers)
Q: "Why not use blockchain?" A: "Blockchain is overkill for this use case. We need speed and zero infrastructure. Our SHA-256 hash chain gives the same immutability guarantee without gas fees, nodes, or mining. It runs in a browser on any government computer." (Abhidnya answers)
Q: "What if the content is a scanned PDF, not text?" A: "The system hashes any content string. In a production version, we'd hash the binary file itself — the principle is identical. For this demo, we use text to make the hash-change visible." (Sanika answers)
Q: "How does the email alert work?" A: "We use EmailJS — a client-side email service. The moment the hash mismatch is detected, an automated email fires to the registered authority with the full breach report: who, when, and the cryptographic proof." (Franklin answers)
Q: "Is this deployed somewhere?" A: "Yes, it's live on Netlify. The QR code on your handover paper links directly to it. You can try it right now on your phone." (Any member)
Q: "What's the future scope?" A: "Government API integration, Aadhaar-based custodian verification, mobile app for field officers, and optional blockchain anchoring for high-value documents like land records." (Abhidnya answers)
